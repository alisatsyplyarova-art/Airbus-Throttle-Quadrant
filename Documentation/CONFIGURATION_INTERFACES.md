# Интерфейсы конфигурации / Configuration Interfaces

**Статус:** архитектура запланирована; реализация ещё не начата.  
**Контроллер:** Arduino Pro Micro ATmega32U4.  
**Цель:** один слой конфигурации и калибровки, два интерфейса управления: OLED на квадранте и Windows/PySide6.

## 1. Архитектурный принцип

OLED и Windows-программа не реализуют калибровочную математику независимо. Оба интерфейса вызывают один и тот же слой конфигурации прошивки. Прошивка остаётся ответственна за валидацию, преобразование RAW в HID, фильтрацию и сохранение EEPROM.

USB HID должен продолжать работать, если Windows-конфигуратор закрыт, Serial отключён или экран перерисовывается.

## 2. Вариант A — OLED на квадранте

- Выбранный модуль: OLED 0,96″, 128×64, контроллер SSD1315, интерфейс I²C, питание 3,3 В; по описанию продавца четыре независимых контакта кнопок K1–K4 и размер 44,53×27,66 мм.
- Подключение дисплея: общая I²C-шина с TCA9548A и двумя AS5600. Адрес 0x3C предварительный; проверить реальный адрес, совместимость библиотеки/инициализации SSD1315 и устойчивость общей шины на аппаратуре.
- Кнопки: UP / DOWN / OK / BACK подключаются через K1–K4. GPIO не назначены до проверки распиновки модуля и свободных выводов Pro Micro.
- Меню: Calibrate L, Calibrate R, Invert, Filter, Save, Reset. UP/DOWN перемещают выбор, OK подтверждает, BACK возвращает или отменяет.
- Калибровка: указать рычаг → поставить IDLE → ОК → поставить TOGA → ОК → проверить диапазон → подтвердить.
- Экран состояния: шкалы L/R, RAW, нормализованное/HID значение и состояние магнита AS5600.
- Диагностика: ERR_READ, ERR_CAL, ERR_EEPROM; предусмотреть отмену и возврат без сохранения.

## 3. Вариант B — конфигуратор Windows

- Стек: Python, PySide6, pyserial.
- Вкладка «Калибровка»: две живые шкалы L/R.
- Отдельные кнопки «Запомнить IDLE» и «Запомнить TOGA» для каждого рычага.
- График сырых углов с ограниченной историей точек, чтобы не накапливать данные бесконечно.
- Индикаторы MD/ML/MH для каждого AS5600.
- Инверсия и параметр фильтра с отображением текущего значения.
- Действия «Сохранить в EEPROM» и «Сбросить настройки».
- Ошибки и версия протокола должны быть видны пользователю; потеря соединения не должна блокировать GUI или HID.

## 4. Общий USB Serial-протокол

Транспорт: UTF-8/ASCII, одна команда на строку, окончание строки LF; точная грамматика и формат ответа фиксируются до реализации приложения. В каждой версии прошивки передаётся версия протокола. Запросы должны быть неблокирующими для основного цикла датчиков и HID.

Минимальный набор команд:

| Команда | Назначение |
|---|---|
| `GET_STATUS` | Версия прошивки/протокола, RAW/HID L/R, состояния датчиков и ошибки |
| `GET_CONFIG` | Прочитать активные настройки |
| `CAL_START L` / `CAL_START R` | Начать калибровку выбранного рычага |
| `CAL_MARK_MIN L` / `CAL_MARK_MIN R` | Зафиксировать конец IDLE |
| `CAL_MARK_MAX L` / `CAL_MARK_MAX R` | Зафиксировать конец TOGA |
| `SET_INVERT L 0|1` | Пример команды установки инверсии; окончательная грамматика подлежит фиксации |
| `SET_FILTER <value>` | Пример команды настройки фильтра; допустимый диапазон должен быть специфицирован |
| `SAVE_CONFIG` | Проверить и записать конфигурацию в EEPROM |
| `LOAD_DEFAULTS` | Загрузить значения по умолчанию в RAM; сохранение — отдельным действием |

Каждый запрос получает однозначный ответ: `OK` или `ERR <code>`, с версией протокола/идентификатором запроса в окончательной спецификации. Нужны максимальная длина строки, защита от частичных команд, обработка неизвестных команд и проверка диапазонов.

## 5. EEPROM

Структура конфигурации должна содержать:
- сигнатуру/магическое значение;
- версию схемы конфигурации;
- параметры L и R: границы калибровки, инверсию, настройки фильтра;
- резерв для дальнейших параметров детентов и дополнительных органов управления;
- CRC для обнаружения повреждения.

При старте проверить сигнатуру, версию, CRC и допустимость каждого поля. При ошибке загрузить безопасные значения по умолчанию и сообщить ERR_EEPROM/диагностический статус. Обновления схемы делать явно. Не записывать EEPROM в каждом цикле: только по явной команде/подтверждённому действию пользователя.

CRC обнаруживает случайное повреждение, но не заменяет проверку диапазонов. Для тестов предусмотреть повреждённые данные, неподдерживаемую версию, неверную CRC и отключение питания вокруг операции записи.

## 6. Статусы магнитного поля AS5600

Регистр STATUS 0x0B:
- MD — магнит обнаружен;
- ML — поле ниже рекомендуемого диапазона;
- MH — поле выше рекомендуемого диапазона.

Интерфейс должен отображать эти биты раздельно. Не следует называть ML/MH точным измерением расстояния: это только качественные флаги состояния магнитного поля.

## 7. План реализации

1. Зафиксировать формат конфигурации, версию протокола, коды ошибок и правила валидации.
2. Реализовать независимые от UI функции конфигурации/калибровки и EEPROM.
3. Добавить host-тесты круговой калибровки, CRC и проверки структуры.
4. Реализовать Windows-конфигуратор первым — для ускорения настройки и диагностики.
5. Реализовать OLED и три кнопки, повторно используя тот же слой.
6. Провести аппаратную проверку совместной I²C-шины, EEPROM после перезапуска, калибровки через 4095→0, ошибок датчиков и работы HID при отключённом Serial.

## 8. Ограничения и открытые проверки

- До подтверждения схемы нельзя считать D8/D9/D10 окончательным назначением кнопок.
- OLED добавляет 1024 байта буфера кадра при полном framebuffer; на ATmega32U4 с ограниченной SRAM нужно проверить фактическое потребление памяти и при необходимости использовать облегчённый режим/библиотеку.
- I²C-адрес 0x3C нужно подтвердить сканированием конкретного модуля.
- Документ описывает план, а не реализованные или аппаратно проверенные функции.

# English summary

The selected OLED module is 0.96-inch 128×64 SSD1315, I²C, 3.3 V, with four independent K1–K4 button interfaces. GPIO mapping, I²C address (expected 0x3C), and SSD1315 library/initialization remain subject to hardware verification. The OLED and Windows/PySide6 configurator will share one firmware configuration/calibration core over a versioned USB Serial protocol. The EEPROM record will include a signature, schema version, settings and CRC; all fields will also be range-validated. The Windows configurator is planned first, followed by the onboard OLED. GPIO assignments and shared-bus operation remain subject to hardware verification.
